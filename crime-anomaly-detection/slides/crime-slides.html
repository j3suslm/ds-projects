Anomaly Detection in Crime

A Case Study for Mexico

Author

Jesus L. Monroy

Published

Feb 23, 2026

Overview

Crime data is inherently “noisy.” A Saturday night in a downtown district will naturally have more incidents than a Tuesday morning in the suburbs.

A simple threshold (e.g., “alert me if crimes > 20”) doesn’t work because it ignores context like seasonality, day of the week, and location-specific baselines.

To solve this, we move beyond simple counting and toward Unsupervised Machine Learning.

This case study is based on fictituos data only.

The Tech Stack

  • Polars.

Unlike Pandas, Polars is built in Rust and uses multi-threading. When processing millions of crime logs, Polars can be 10–100x faster, making it the ideal engine for real-time analytics.

  • Scikit-Learn.

We wil use the Isolation Forest model. This algorithm is a “forest” of trees that tries to isolate each data point. Anomalies are “easy to isolate” (they require fewer splits in the tree), while normal points are “hard to isolate.” This makes it incredibly effective at finding rare events in unlabeled data.

  • Plotly.

Static charts are dead in crime analysis. Detectors need to zoom in on specific dates and hover over data points to see metadata. Plotly provides this interactivity natively.

From Raw Logs to Red Flags

  1. Data Synthesis & Cleaning

We study a year of crime data across two districts: “Downtown” (high volume) and “Suburbs” (low volume).

  1. Feature Engineering

A crime count of “25” means something different on a Monday than it does on New Year’s Eve. We use Polars to extract features like day_of_week and month. This allows the machine learning model to understand the rhythm of the city.

  1. Training the Isolation Forest

We feed the counts and temporal features into the Isolation Forest. We set a contamination parameter (0.02), telling the model we expect about 2% of our data to be anomalous. The model then assigns an “anomaly score” to every single day in the dataset.

Modelling

# Isolation Forest "isolates" observations by randomly selecting a feature and split value.
# Anomalies are easier to isolate and thus have shorter paths in the trees.
model = IsolationForest(contamination=0.02, random_state=42)

# Convert to numpy for sklearn (using Polars' fast selection)
X = df.select(["incident_count", "day_of_week", "month"]).to_numpy()

df = df.with_columns(anomaly_score = model.fit_predict(X))

# Convert -1 (anomaly) and 1 (normal) to readable labels
df = (
    df.with_columns(
        is_anomaly = pl.when(pl.col("anomaly_score") == -1)
                        .then(pl.lit("Yes"))
                        .otherwise(pl.lit("No"))
    )
)

Conclusions

The output is an interactive dashboard. While a human might miss a slight but statistically significant rise in suburb crime during October, the model flags it instantly in bright red.

  • Downtown: The model successfully identified the July 4th spike as an anomaly, distinguishing it from the already high daily average.
  • Suburbs: It caught a smaller “micro-spike” in mid-October that might have been overlooked by manual review.

This approach shifts law enforcement from reactive to proactive. By identifying anomalies in real-time, departments can:

  • Allocate patrols to “hot zones” before a trend scales.
  • Identify potential new “modus operandi” used by organized groups.
  • Validate whether a specific community intervention is successfully reducing crime below the expected baseline.
